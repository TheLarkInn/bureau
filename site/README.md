# Bureau public site

An original, static introduction to Bureau, published at
<https://thelarkinn.github.io/bureau/>. No custom domain. The page is not the
local dashboard: it never queries Bureau state, accepts credentials, starts
work, or connects to a local or cloud control API.

The sample run is explicitly illustrative. Its controls switch fixed text;
they do not simulate or execute agent work. All content and links work without
JavaScript. Enhancements add sample states, scenario filtering, and architecture
labels. There are no fonts, scripts, analytics, or images from external hosts.

## Build and preview

Node.js 24 is the only build dependency. Run from the repository root:

```sh
node site/build.mjs --base /bureau/ --origin https://thelarkinn.github.io
node site/serve.mjs
```

Open the printed loopback URL, normally `http://127.0.0.1:4173/bureau/`.
For a deliberately root-mounted preview:

```sh
node site/build.mjs --base /
node site/serve.mjs --port 4174
```

The preview serves only the eight whitelisted public files, only over
loopback, and only for GET/HEAD. It verifies build hashes before listening.
Unknown routes return HTTP 404 with a base-correct home link; it is not an
SPA catch-all. It never serves the source tree or local configuration.

`--origin` only adds canonical metadata. Omit it for local previews; no
deployment domain is embedded in asset URLs. `--base` accepts `/` or
slash-delimited segments such as `/bureau/`. Output defaults to `site/dist`;
`--out` can select an empty output directory. Existing unrecognized files or
symlinks fail the build instead of being silently removed.

The build copies explicit public inputs, resolves template tokens, verifies
local links/anchors, and writes deterministic SHA-256 metadata. Public files
must total at most 256 KiB. No configuration, state, credentials, source maps,
or `CNAME` are included. The output and test evidence are ignored by Git.

Input reads use the shared file-descriptor-bounded reader: at most 256 KiB
per source/public file and 16 KiB for the preview manifest. Each read checks
the opened descriptor and allocates only its limit plus one lookahead byte,
so growth after a size check cannot cause an unbounded read. Preview
manifests also require valid UTF-8. These are file/output limits, not a
256 KiB cap on the entire Node process.

## Content contract

`src/index.html` and `src/404.html` are the page templates. Original styles,
the mark, and progressive enhancement live under `src/assets/`. `content.mjs`
contains the six operating principles and ten scenario entries. Scenario
links target `docs/scenarios.md` and the stable IDs in
`examples/scenarios/catalog.json`; examples remain authoritative, hand-edited
configuration, never generated by the website.

The site distinguishes ordinary local ACP pipelines, qualification-required
local SDK factories, and experimental cloud controls. It makes no general
availability or live-entitlement claim. Cloud work does not inherit local
pipeline budgets or execution controls.

Release links go to the current published release, not a hardcoded version or
an unverified download URL. Architecture labels match `scripts/release-assets.mjs`.
The setup, factory, cloud, and canvas source links point to their actual guides.

## Offline validation

The dependency-free checks live in `scripts/site*.test.mjs` and
`scripts/pages-*.test.mjs`; the repository's `scripts/lint.sh` includes them.
This dedicated wrapper also rejects skipped tests and empty/failed TAP:

```sh
node site/test.mjs
node site/build.mjs --base /bureau/ --origin https://thelarkinn.github.io
node site/verify-links.mjs
```

`verify-links.mjs` checks documentation file bytes and Markdown anchors in
the **same checkout**, without network requests. The setup/catalog slice,
including `docs/scenarios.md`, must be integrated before this gate can pass.
Changing a document anchor without updating the site fails CI.

Browser checks reuse the existing canvas Playwright lockfile; there is no
second browser dependency tree. The small `site/package.json` adds only
`axe-core` for offline WCAG auditing. Install prerequisites explicitly, once:

```sh
(cd .github/extensions/bureau-canvas/e2e/playwright && npm ci --ignore-scripts && node node_modules/@playwright/test/cli.js install --with-deps chromium)
(cd site && npm ci --ignore-scripts)
```

On Windows, run the `npm ci` commands from those package directories in
PowerShell. New browser caches and temporary files can be directed to the
work drive with `PLAYWRIGHT_BROWSERS_PATH`, `TEMP`, and `TMP`. Never run these
checks alongside another browser job on a resource-constrained host.

```sh
node site/browser.mjs
node site/check.mjs --kind accessibility --json
node site/check.mjs --kind responsive --json
```

Playwright uses one worker, zero retries, no video or traces, and a finite
150-second suite deadline. It checks both `/bureau/` and `/`, keyboard use,
sample states, all scenario links, architecture labels, 320/375/768/1440px
layouts, a half-width reflow check, reduced motion, no-JavaScript use, and
real 404 behavior. Six full-page screenshots and two viewport crops, each
capped at 2 MiB and 16000px page height, plus at most one viewport failure
screenshot per test, are the bounded visual evidence.

Accessibility uses actual Chromium and axe against desktop sample states,
mobile, and the 404 for both bases. It checks WCAG A/AA through 2.2 and
best-practice rules. Automated results do not replace human accessibility
review. An axe result requiring manual review is incomplete, not a pass.
Responsive audits check 320/375/768/1024/1280/1536px at both bases, every sample
state, filtered scenarios, ARM64 labels, horizontal containment, clipping, and
standalone 24px targets. These are layout audits, not a claim of complete
WCAG conformance or real browser zoom certification.

### Maintenance adapter contract

Each `check.mjs` call writes exactly one JSON object to stdout:

```json
{"schema":"bureau-site-check-v1","kind":"responsive","complete":true,"checks":144,"findings":[],"bases":["/bureau/","/"]}
```

Findings have stable `id`, `title`, `detail`, and repository-relative `path`;
an optional `line` may be added later. Reports hold at most 20 distinct
findings, with IDs/titles up to 160 characters and details up to 4000.
The same finding across viewports is reported once. Exceeding the finding
count makes the audit incomplete instead of silently dropping findings.
Exit 0 requires positive completed
checks and no findings; 1 means completed checks with findings; 2 means
missing tools, interrupted/incomplete checks, or invalid input. There is no
skip-success or static fallback. Missing packages/browsers are never installed
by the runner.

Fresh maintenance worktrees should not trust ignored, agent-writable
`node_modules`. Set `BUREAU_SITE_TOOLS` to an absolute, pre-provisioned,
**read-only** tool root with this layout:

```text
/opt/bureau/site-tools/
  site/
    package.json
    package-lock.json
    node_modules/axe-core/...
  .github/extensions/bureau-canvas/e2e/playwright/
    package.json
    package-lock.json
    node_modules/@playwright/test/...
    node_modules/playwright/...
    node_modules/playwright-core/...
```

Provision those package directories with their exact committed manifests and
lockfiles using `npm ci --ignore-scripts` outside any agent run. Set
`PLAYWRIGHT_BROWSERS_PATH=/opt/bureau/browsers` to a separately preinstalled, read-only Chromium
cache. The resolver compares all four manifest/lockfile bytes to the protected
checkout, checks the direct package versions, and confines resolved modules
to the selected package's `node_modules`. A missing or mismatched external
tree fails explicitly; it never falls back to worktree or ambient modules.
Lock matching does not prove every installed byte: trusted provisioning and
the read-only mount are required, not replaced by the resolver.

One audit uses one Chromium tree and one page at a time, starts closing the
browser at 110 seconds, and emits at most 128 KiB. The caller must supervise
the entire process group with a 150-second ceiling and enforce its own
memory/disk admission. Reserve at least 1 GiB memory and 128 MiB temporary
working space, excluding the preinstalled browser/dependencies. Temporary
previews live under `site/.cache/` and are removed on ordinary exit. Temporary
browser profiles follow the platform temp directory.

Automatic accessibility/responsive repairs may change **`site/src/**` only**.
Protect all build/audit/test scripts, `content.mjs`, manifests, lockfiles,
workflows, and `scripts/`: changing the evaluator is not a valid repair.

## CI and publication

`site-checks.yml` is a read-only reusable workflow. It checks one immutable
source SHA on Ubuntu 24.04 using Node 24, one browser worker, finite command
and job timeouts, and bounded artifacts. It is a required dependency of CI's
existing **All checks passed** aggregate, so a site failure also blocks a
release or release-PR merge. There is no separate merge bypass.

`pages.yml` validates pull requests without Pages write permissions or
repository secrets. Main pushes and manual runs build and check the same
source before deployment. Publishing is restricted to `TheLarkInn/bureau`
and `refs/heads/main`; source admission and the deploy job both check main's
exact SHA. Forks, other branches, tags, unsupported events, and stale runs
cannot publish. No `pull_request_target` or user-selected source input exists.

Only the deployment job has `pages: write` and `id-token: write`. It checks
out and executes no repository code: it publishes the same-run checked
artifact. PRs never upload a Pages artifact. Deployments cancel superseded
runs; ordinary CI keeps its existing release concurrency behavior.
Failure screenshots/JSON are retained for seven days; the Pages artifact
for one day. No private operational data enters either artifact.

After integrating all slices and passing the protected CI gate, a repository
maintainer can select **GitHub Actions** as the Pages source in repository
settings and restrict the `github-pages` environment to main. Then run
**Bureau Pages** on main. The workflow explicitly disables Pages enablement;
it does not create a site, change repository visibility, or configure a
custom domain. Token-created release merges may not trigger a Pages push
event; a main-only manual run is the deliberate recovery path.

The required repository gates remain unchanged:

```sh
cargo fmt --all
bash scripts/lint.sh
cargo test --offline
```
